# 财搭子研究看板 · DSH 插件

把三个研究问题放进 DeepSeek Harness：**存储涨价能否兑现利润、AI 基建能否赚回投入、PCB／CCL 规格升级能否变成订单**。

这是可安装的研究增强预览版（v0.1.2）。看板通过个人财搭子 API Key 获取行情与研究线索；继续研究时，将看板问题和情景参数带入 DSH 原生会话。

## 安装

需要 Node.js **24.9.0+**、DeepSeek Harness **0.2.2-rc.2**。已实测该版本 Web 界面；不宣称支持其他版本或 Desktop 内置通信。

```sh
npm install -g @deepseek-ai/dsh@0.2.2-rc.2
dsh plugin --profile web add https://github.com/markthc/dsh-caidazi-boards/releases/download/v0.1.2/caidazi-dsh-boards-0.1.2.tgz
dsh web
```

也可下载 Release 中的 `.tgz`，执行 `dsh plugin --profile web add ./caidazi-dsh-boards-0.1.2.tgz`。包已预编译，安装不用执行本插件的构建脚本。

1. 打开 DSH 左侧的 **财搭子看板**。没有 Key 时只展示截至2026-11-12的研究内容与不可调整的测算预览，不请求财搭子数据。
2. 点击 **连接财搭子**，粘贴财搭子 App → 大发 → 左侧菜单 → 我的skill → 领取 API Key（已领取则进入「我的API KEY管理」复制）。插件会实际请求行情验证，成功后保存到 DSH 凭据区。也支持宿主进程已有的 `CAIDAZI_API_KEY`。
3. 默认打开 **研究判断**，先读结论、财务图表和反证条件。三张看板首次打开时自动加载行情；在 **行情与线索** 点击 **刷新行情与资料** 更新接口数据。研究判断不会被行情刷新改写。没有后台轮询或定时任务。
4. **继续研究** 或单项研究入口打开 DSH 会话草稿，已带入问题与参数；检查后发送。需要 DSH 自身已配置可用的模型。回到看板保留本次页面内的数据、选项与参数；重新加载浏览器后重新读取。

## 三张看板

| 看板 | 交付 |
| --- | --- |
| 存储产业跟踪 | 利基与主流存储分化、长约价带及供给响应；三星季度资本开支柱图；兆易分时和美光报价 |
| AI 基建 · 成本与回报 | CoreWeave 3Q26收入图与现金／授信／预付款／在建资产拆分，项目交付与续租风险；新增CRWV报价，保留情景测算 |
| PCB／CCL · 升级兑现 | 胜宏HDI收入／毛利、经营现金流／扩张支出柱图；排单与验收、每股收益和现金兑现；新增胜宏报价 |

- **数值层**：`get_real_time_record`、`get_a_share_history_1m_price`。只显示实际返回的报价与最近两个可用交易日的分钟收盘价；补点/未完成点留空。图表写明币种、口径、日期与时间。
- **资料层**：`investment_search_pro`。仅展示 `authorized` / `citation_only` 的标题、出处与原文链接；过滤无关内容、过期资料、未来日期和原文日期冲突。不转发新闻全文或机构研报图片。
- **研究快照**：`src/research.js` 保存有日期的研究判断、公开原始来源和四张财务柱图。事实、公司展望与机构观点分别标明；不公开知识库原件或报告全文。研究更新需修改内容并发布新版本，不是MCP实时财务序列。
- **研究层**：注册官方 `@caidazi/mcp@0.2.10` 内的 8 个 Skills 和 MCP 工具。DSH 会话使用用户自己的模型继续分析。看板不把价格上涨自动转成投资结论，也不将缺资料判成检查通过。
- **情景层**：AI 基建默认 `100亿元 × 15% ÷ 24% = 62.5亿元/年`，全部是可改假设，不是某家公司的披露或预测。回报目标指净利润／投产资本，不是IRR；模型不含建设期、融资杠杆和后续追加投入。

## 连接和边界

Key 只从浏览器提交给本地 DSH，再由宿主传给财搭子官方 MCP bridge；不放入 URL、浏览器持久化、聊天或分享文件。接口沿用 DSH 的浏览器认证、Host/Origin 检查与 owner 权限。DSH 本地凭据文件不等同于操作系统级密钥隔离。

看板本身只读公共数据；不会读取持仓、修改自选、创建监控或执行交易。配套官方 Skills/MCP 包含个人资产等工具，只有用户后续提出相关请求时才应使用。Key 的账户权益、额度与撤销由财搭子服务端决定；本插件不新增收费或承诺数据 SLA。

当前行情可能延迟，报价旁展示的是接口交易时间；美股接口未标时区时如实注明。历史行情有时返回非连续交易日，以实际日期为准。2026-11-12本轮三板的行情、历史和参考公司报价均成功，搜索接口也成功，但筛选后可展示资料均为0条。这是资料交付缺口，不等于市场没有新闻。

**尚未接入**：DRAM/NAND 连续产品价格、企业季度 CAPEX/利润/现金流的自动更新序列、云端持续监控、收藏/fork 同步、注册和发 Key 页面。这些需要财搭子补充数据或产品接口。完整基本面结论仍需在会话中完成，不能将本预览版当成全部研究数据已自动化。

## 开发

```sh
npm ci
npm test
npm run build
npm pack
```

源文件 `src/host.js` 负责原生接入及鉴权，`src/data.js` 负责三个固定工具的数据解释与权限筛选，`src/client.jsx` 为主面板，`src/research.js` 与 `src/research-view.jsx` 管理有日期的研究内容及图表。不存在单独的 Web 后端、数据库或新增框架。

代码采用 MIT。财搭子 Logo 和大发头像复用财搭子 Flutter 素材，品牌和商标权利仍归财搭子所有，不随代码许可转让。数据与第三方服务遵循各自许可和账户条款。发布包不含任何用户 Key、持仓、测试响应或机构材料。

## 定时分析、数据刷新与监控

基于 DSH 0.2.2-rc.2 的官方 Schedule / Webhook 实现：

| 需求 | DSH 机制 | 此插件当前状态 |
| --- | --- | --- |
| 固定时间研究 | Host 保存任务，到时将指令投递到会话，由 Agent 调用模型和 MCP | 可以在原生 Automation tasks 配置；结果进入会话 |
| 定时更新看板数据 | 需要任务将结果写入看板共用的数据存储，再让页面读取 | 尚未接入；当前是首次打开与手动刷新 |
| 指标或事件变化立即研究 | 外部事件源 → 认证 Webhook → 规则 → 会话 | DSH 有底层机制，但财搭子事件源与适配器尚未接入 |

### 现在可以怎么用

在 DSH 的 Automation tasks 创建一个任务，时区设为 `Asia/Shanghai`，每个工作日 18:00，目标选择首次创建后复用同一会话（`new_once`）。任务示例：

> 使用财搭子 MCP 跟踪存储行业。获取兆易创新、美光最新报价与相关公告，比较上次研究的产品价格、供给和利润兑现证据。仅在出现有原始来源的新事实或判断变化时详细报告；没有实质变化则简短说明。注明数据日期，不把重复新闻当新事件，不访问个人持仓或执行交易。

这会定时生成会话研究结果，**不会自动刷新看板页面**。工作日规则不是证券交易日历，节假日仍可能有海外行情或公告。

任务支持单次、间隔、每日、每周、五字段 cron、RRULE；间隔最低60秒。建立任务不调用模型，执行研究时会消耗模型和数据服务额度。Host 必须运行：关闭浏览器不影响仍在运行的 Host，退出 Host／关机则无法准时执行；恢复后遗漏周期只补最近一次。投递记录只证明指令进入会话，不代表研究完成；崩溃时可能重复投递。

### 看板定时更新的最小后续改造

复用现有 `loadBoard`：提供 Agent 可调用的固定看板刷新工具，成功后在 Host 保存每张板的最新快照、版本与时间；手动刷新也写入同一处。页面打开及数据变更时读取该快照，失败保留上次成功数据。Schedule 调用刷新工具后，页面与会话才能共享结果。

纯行情刷新可由确定性定时程序完成，不需要每次启动模型；有事件变化或需要解释时再触发 Agent 分析。持续监控优先由财搭子云端执行，DSH 作为消费入口，避免依赖用户电脑全天开机。事件推送还需财搭子提供带认证、事件编号的数据出口；DSH Webhook runtime 本身不提供队列、重试或去重，不能直接当可靠监控服务。财搭子 MCP 现有监控列表读取能力不等于创建云任务能力。

本版没有自动创建任何定时任务，也没有在页面里展示尚未落地的“自动更新”开关。

官方依据：[Schedule](https://github.com/deepseek-ai/deepseek-harness/blob/main/docs/subsystems/schedule.md)、[Webhook](https://github.com/deepseek-ai/deepseek-harness/blob/main/docs/subsystems/webhook.md)。领取 Key 的步骤依据本轮读取的 Flutter Skills 页面和左侧菜单实现；具体上架版本需与 App 发布进度对齐。

## 当前潜在问题与改进顺序

1. **研究容易过期**：本版研究截至2026-11-12，刷新行情不会重核判断。优先接入财搭子服务端的版本化研究结果、事件更新和定频复核，再向用户承诺持续跟踪。
2. **决定判断的行业数据仍缺**：存储合同价／合格bit、数据中心项目验收、PCB良率等未形成可自动更新的序列；价格走势只能作市场参照。先补每板最关键的2—3项证据，不能用报价代替。
3. **行业板可能被单家公司主导**：AI目前以CoreWeave为重点案例，PCB新增证据集中胜宏，三星图是集团投入。应补同口径公司对照；这些数据不能外推整个产业链。
4. **近期线索暂未交付**：本轮搜索筛后3板均0条，需与数据团队核查权限标记、发布时间及原文日期，不能简单取消过滤或填入旧新闻。
5. **Agent交接不等于研究完成**：本轮验收到原生会话草稿、参数及研究版本；测试DSH未配置模型，未验证最终分析质量。财务情景也只是简化静态计算。
6. **分发与持续运行有门槛**：当前是GitHub预览包，需兼容版本的DSH和财搭子Key；Host停机无法按时研究，定时会话结果尚不能回写看板。

机构报告观点只作用户提供材料的摘要，第三方无法从公开包核验全文。关键数值优先链接公司公告；CoreWeave电话会部分采用知识库留存官方稿，页面链接为IR入口，仍有查证摩擦。
